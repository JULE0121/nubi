# NUBI — 날씨에 맞춰 지키는 여행 일정

날씨에 맞춰 여행 일정을 조정하고 대체 관광지를 추천하는 대학교 과제 프로젝트입니다.

## 목표
여행 일정 입력 → AI 일정 인식 → 사용자 확인·수정 → 날씨 적합도 판단 → 유사 관광지 추천 → AI 일정 재구성.
KNIME은 날씨 적합도와 관광지 유사도를 분석하고, Python은 분석 결과·거리 등을 이용해 추천 순위를 계산합니다.

## 현재 상태
관광지 323곳의 정보를 읽고, 테마와 거리를 이용해 대체 관광지를 추천하는 Python 코드를 만들었습니다. 현재 위치와 기존 일정 위치를 기준으로 추천할 수 있습니다. Streamlit은 시작 화면만 있고, 실제 날씨·지도·AI 연결은 아직 진행하지 않았습니다.

## 폴더
- `data/raw/`: 출처를 기록한 원본 관광지·날씨·방문객 자료
- `data/processed/`: KNIME 정리·분석 결과
- `knime/`: KNIME 워크플로우
- `src/`: Python 추천 및 API 연결 코드
- `docs/`: 개발 순서와 설계 기록
- `app.py`: Streamlit 시작 화면

## 실행
Python 환경에 의존성을 설치한 뒤 실행합니다. 가상환경을 만든 뒤 의존성을 설치합니다.

```bash
cd ~/jule/nubi
python3 -m venv ~/.venvs/nubi
source ~/.venvs/nubi/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

API 키는 `.env`에 저장하고 Git에 추가하지 않습니다.

## 월별 날씨 적합도 규칙 검증용 초안

데이터 파일: `data/processed/weather_suitability_monthly_draft.csv`

KNIME으로 관광지와 기상 관측소를 연결하고 월별 기상 관측 데이터를 기반으로 날씨 적합도를 분류한 결과입니다. **월 단위 규칙을 시험하기 위한 초안이며, 실시간 관광지 추천에 직접 사용하지 않습니다.**

- 구성: 관광지 323곳, 8,075행, 17개 컬럼. 관광지 식별 컬럼은 `관광지ID`입니다.
- 검증: 전체 행 중복 및 관광지ID·월 조합 중복은 없습니다.
- 판정: 적합 3,202행, 보통 2,918행, 부적합 1,926행, 판단보류 29행입니다. 판단보류는 결측 등으로 판정할 수 없는 경우를 구분하는 값입니다.
- 강수량 결측 35행 중 실외 29행은 판단보류, 실내 6행은 적합으로 처리했습니다. 실내를 항상 적합으로 보는 것은 이번 초안의 단순화된 규칙입니다.

### 해석 및 향후 적용

CSV에 최고기온 컬럼은 있지만, 이번 적합도 판정에는 최고기온 33℃ 조건이 반영되지 않았습니다. 월 합계 강수량 200mm 기준과 월 평균기온 기준을 일 단위 예보에 그대로 적용해서는 안 됩니다.

실시간 추천 기능에서는 일 단위 날씨 API의 일 강수량과 일 최고기온을 기준으로 임계값 및 결측 처리 기준을 별도로 설계합니다. 이번 초안에서는 적합·보통·부적합의 판정 구조와 실내외 구분 방식만 참고하며, 실내 시설의 운영 여부와 특성도 이후 검토합니다.

## Python 추천 기능

지금은 복잡한 모델 대신 테마와 거리를 기준으로 추천합니다. 아직 완성된 서비스는 아니며, 결과를 보면서 기준을 조정할 예정입니다.

| 파일 | 하는 일 |
| --- | --- |
| `src/attractions.py` | 월별 CSV에서 관광지ID 중복을 제거해 관광지 정보를 읽음 |
| `src/similarity.py` | 테마 유사도 표에서 점수를 찾음 |
| `src/distance.py` | 위도·경도로 두 장소 사이의 거리(km)를 계산함 |
| `src/weather.py` | KNIME 월별 날씨 규칙을 Python으로 계산함 |
| `src/recommend.py` | 조건에 맞는 후보를 골라 추천 순서를 정함 |

### 추천 기준

- `itinerary`: 기존 관광지 주변에서 추천합니다.
- `current`: 현재 위치 주변에서 추천합니다. 관광지ID도 넣으면 그 관광지의 테마를 함께 고려합니다.
- `both`: 현재 위치와 기존 관광지까지의 평균 거리를 사용합니다. 결과에는 각각의 거리도 표시합니다.
- 최대 거리를 지정하면 그 안의 후보만 남깁니다. `both`는 두 위치에서 모두 제한 거리 안에 있어야 합니다.
- 실내 또는 실외를 선택할 수 있습니다. 기존 관광지 자신은 추천에서 제외합니다.
- 관광지ID가 있으면 `테마 유사도 × 0.6 + 거리 점수 × 0.4`로 계산합니다.
- 거리 점수는 `1 / (1 + 거리_km / 10)`입니다. 관광지ID가 없으면 거리 점수만 사용합니다.
- 60:40 가중치와 10km 기준은 처음 시험해 보는 값이며, 검증된 최적값은 아닙니다. 테마 점수도 현재 사용 중인 초기 비교 기준입니다.

### 날씨 옵션

`--month`는 저장된 월별 자료로 규칙을 확인하는 용도입니다. 기본은 `적합`만 추천합니다. `--include-normal`을 추가하면 적합한 후보를 먼저 보여주고, 개수가 부족한 경우에만 `보통`으로 채웁니다. `부적합`과 `판단보류`는 제외합니다.

Python 함수의 `weather`에는 `{"T001": "적합", "T002": "보통"}`처럼 관광지별 테스트 판정을 넣을 수 있습니다. 누락된 관광지는 판단보류로 처리하고, `month`와 동시에 사용할 수 없습니다. API의 기온·강수량을 바로 넣는 기능은 아닙니다. 날씨 옵션을 쓰지 않으면 결과에 `날씨 미반영`으로 표시합니다.

### 실행 예시

프로젝트 폴더에서 실행합니다.

```bash
# 기존 관광지에서 30km 이내 추천
python3 -m src.recommend T039 --max-distance-km 30

# 현재 위치에서 20km 이내의 실내 관광지 추천
python3 -m src.recommend --location-mode current --user-lat 38.244892 --user-lon 128.572088 --max-distance-km 20 --indoor-preference 실내

# 두 위치에서 각각 30km 이내 추천
python3 -m src.recommend T039 --location-mode both --user-lat 38.25 --user-lon 128.56 --max-distance-km 30

# 월별 초안 확인: 적합 후보가 부족하면 보통 후보로 보충
python3 -m src.recommend T039 --month 2025-02 --include-normal
```

기본 추천 개수는 5개이고 `--top-n`으로 바꿀 수 있습니다. 조건에 맞는 장소가 없으면 조건을 자동으로 풀지 않고 결과가 없다고 안내합니다.

### 아직 부족한 점

좌표로 계산한 거리는 실제 도로 이동거리나 이동시간과 다릅니다. 날씨 API를 연결한 뒤에는 방문 시간에 맞는 일 단위 판정 기준을 따로 만들어야 합니다. 실내외 구분과 테마는 CSV 값을 그대로 사용하므로 잘못 분류된 관광지는 데이터도 확인해야 합니다. 운영 시간이나 여행 일정 전체의 동선 최적화는 아직 반영하지 않았습니다.

## Streamlit 웹 애플리케이션

NUBI는 사용자의 여행 일정과 위치를 바탕으로 관광지를 추천하는 서비스입니다.

### 현재 구현 기능
- 관광지 데이터 기반 추천
- 현재 위치 및 기존 여행 일정 위치를 활용한 거리 계산
- 관광지 테마 유사도 분석
- 실내외 조건에 따른 관광지 필터링
- 테마 유사도 60%, 거리 점수 40%를 반영한 추천 점수 계산
- Streamlit 기반 관광지 추천 화면
- 월별 날씨 적합도 초안 검증

### 실행 방법

프로젝트 폴더에서 다음 명령어를 실행합니다.

```bash
python3 -m streamlit run app.py
```

실행 후 브라우저에서 `http://localhost:8501`에 접속합니다.

### 향후 개발 계획
- Gemini API 기반 대화형 여행 일정 분석 및 수정
- 실시간 날씨 API 연동
- 지도 API를 활용한 경로 및 이동시간 제공
- 날씨 변화에 따른 대체 관광지 추천 자동화
