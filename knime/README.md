# KNIME 분석

NUBI의 데이터 분석과 규칙 설계에 사용하는 KNIME 워크플로우를 저장합니다.
원본 입력은 `data/raw/`, 내보낸 결과는 `data/processed/`를 사용합니다.

## 워크플로우

| 폴더 | 목적 | 현재 범위 |
| --- | --- | --- |
| `nubi-workflow/` | 월별 기상과 관광지 방문객 수의 상관관계 탐색 | 전체 및 관측지점별 선형 상관분석 |
| `NUBI_Recommendation/` | 관광지–관측소 연결과 날씨 적합도 규칙 설계 | 월별 규칙 검증용 초안 CSV 생성 |

### nubi-workflow — 상관관계 탐색

- 입력: 월별 ASOS 기상 데이터, 주요관광지점 입장객 통계
- 흐름: 입장객 데이터 정리 → 시군구별 관측소 매핑 → 관측소·연월 기준으로 기상 데이터 결합 → 평균기온·월 합계 강수량·방문객 수의 선형 상관분석
- 관측지점별 반복 분석은 `관측지점` 컬럼을 기준으로 수행합니다.
- 관측소는 시군구별로 지정한 규칙으로 연결합니다. 관광지 좌표에서 최단 거리를 계산하는 방식은 아니며, 일부 지역은 다른 시군의 관측소에 대응됩니다.
- 상관계수와 통계적 유의성에 관한 결론은 분석 결과표와 함께 정리할 예정입니다.

### NUBI_Recommendation — 월별 적합도 규칙

- 입력: 월별 기상 데이터, 관광지 목록(실내외·테마·좌표), 관측소 목록(좌표)
- 흐름: 관광지–관측소 거리 계산 → 거리순 정렬 및 관광지명·지역 아이디 기준 중복 제거로 가까운 관측소 선택 → 월별 기상 결합 → 적합도 판정 → 중복 관광지 정리 및 관광지ID 연결 → CSV 저장
- 출력: `data/processed/weather_suitability_monthly_draft.csv`
- 현재 출력: 관광지 323곳, 8,075행

## 데이터 처리 기준

관측소까지의 거리가 30km를 넘으면 `거리_신뢰`를 `주의`, 나머지는 `정상`으로 표시합니다.

날씨 적합도는 아래 순서대로 처음 일치하는 규칙을 적용합니다.

1. 실내 관광지: `적합`
2. 실외이며 월 합계 강수량이 200mm 이상: `부적합`
3. 실외이며 월 평균기온이 0℃ 미만 또는 30℃ 초과: `부적합`
4. 실외이며 월 평균기온이 10~25℃이고 월 합계 강수량이 100mm 미만: `적합`
5. 앞선 규칙에 해당하지 않고 월 합계 강수량이 결측: `판단보류`
6. 나머지: `보통`

현재 CSV에는 속초·강릉 관측소의 2025년 2월 강수량 결측에 해당하는 행이 35개 있습니다. 실외 29행은 `판단보류`, 실내 6행은 `적합`입니다.

## 알려진 한계

- 월별 자료는 규칙 검증용 초안이며, 실시간 관광지 추천에 직접 사용하지 않습니다.
- 실제 추천에는 일 단위 날씨 API의 일 강수량·일 최고기온에 맞춘 기준을 별도로 설계합니다.
- 현재 판정에는 최고기온 조건이 반영되지 않았습니다.
- 실내를 항상 적합으로 처리하는 것은 초안의 단순화된 가정입니다.
- 강수량 결측 처리는 월별 행 자체가 없는 경우나 모든 기상 변수의 결측을 포괄하지 않습니다.
- 파일 경로는 로컬 환경의 절대 경로로 저장되어 있어 다른 환경에서는 입력·출력 경로를 다시 지정해야 합니다.
- `data/raw/`의 원본 자료는 Git 추적 대상에서 제외되어 있으므로 별도로 준비해야 합니다.

## 실행 방법

1. KNIME에서 해당 워크플로우 폴더를 불러옵니다.
2. 원본 자료를 `data/raw/`에 준비하고 Reader 노드의 경로를 지정합니다.
3. `NUBI_Recommendation`의 CSV Writer 출력 경로를 확인합니다. 현재 설정은 같은 이름의 파일이 있으면 덮어씁니다.
4. 워크플로우를 실행하고 분석 결과와 출력 CSV를 확인합니다.
